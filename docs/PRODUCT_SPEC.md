# SkyMaster 无人机统一管控平台 · 产品规格书

- **版本**：v1.1-draft
- **日期**：2026-07-08
- **状态**：草案（待评审，v1.1 已纳入 6 项改进意见）
- **对标基线**：大疆司空 2 (DJI FlightHub 2) + QGroundControl + Auterion Suite
- **核心定位**：**自有、开源、私有化部署的多协议无人机统一管控平台**，覆盖司空 2 全部核心能力，并向 PX4 / ArduPilot / DJI / 国产飞控多阵营兼容

---

## 1. 产品定位

### 1.1 一句话定位
> **"能管所有主流无人机的司空 2"** —— 面向政企、应急、电力、警务、巡检、测绘、农业等混编机队场景，提供开源可私有化的统一管控中台。

### 1.2 核心差异化

| 维度 | 大疆司空 2 | SkyMaster |
|---|---|---|
| 支持机型 | 仅 DJI 商用机 + DJI 机场 | **DJI + PX4 + ArduPilot + 国产飞控** |
| 部署模式 | 强绑定阿里云国际 | **公有云 / 私有云 / 离网内网可选** |
| 代码可控 | 闭源 SaaS | **MIT 开源，可深度定制** |
| 数据归属 | 阿里云海外 | **完全自主，符合等保/密评** |
| 二次开发 | 有限 API | **全栈可改，插件市场** |
| 生态锁定 | DJI 独占 | **协议中立，反锁定** |

### 1.3 目标用户

| 客户类型 | 典型场景 | 关键痛点 |
|---|---|---|
| **政府/应急管理** | 森林防火、水利巡检、应急救援 | 数据主权、多厂机型混编、离网部署 |
| **国网/南网** | 输电线路巡检、变电站巡视 | 私有化、大规模机队、AI 缺陷识别 |
| **警用/公安** | 城市巡防、要地安保 | 保密、指挥调度、集群编队 |
| **测绘/规划院** | 倾斜摄影、正射建模 | 任务规划、数据后处理集成 |
| **农业植保** | 大田喷洒、飞防调度 | 极飞/大疆混编、任务下发 |
| **航空运营商** | 商业化机队运营 | 多租户、计费、日志审计 |

## 2. 系统总体架构

### 2.1 分层架构

```
┌────────────────────────────────────────────────────────────────┐
│  接入层 (Presentation)                                          │
│  Web 控制台 · 移动 App · 大屏 · 第三方 API 客户端                │
└─────────────────────────┬──────────────────────────────────────┘
                          │ HTTPS / WSS / gRPC
┌─────────────────────────▼──────────────────────────────────────┐
│  网关层 (Gateway)                                               │
│  Nginx · JWT 认证 · RBAC · 限流 · 审计日志                       │
└─────────────────────────┬──────────────────────────────────────┘
                          │
┌─────────────────────────▼──────────────────────────────────────┐
│  业务层 (Business Services)                                    │
│  设备 · 任务 · 集群 · 直播 · 机场 · 告警 · AI 分析 · 数据回放     │
└─────────────────────────┬──────────────────────────────────────┘
                          │
┌─────────────────────────▼──────────────────────────────────────┐
│  协议抽象层 (Protocol Abstraction Layer, PAL)                   │
│  MAVLink · DJI Cloud API v2 · DJI OSDK · MQTT · 自定义国产协议  │
└─────────────────────────┬──────────────────────────────────────┘
                          │
┌─────────────────────────▼──────────────────────────────────────┐
│  设备接入层 (Device Layer)                                      │
│  PX4/ArduPilot 飞控 · DJI 机场/Mavic/M300 · 国产飞控 · 载荷      │
└────────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────────┐
│  数据/基础设施 (Data Plane)                                     │
│  PostgreSQL · TimescaleDB · Redis · MinIO · Kafka · SRS/ZLM     │
└────────────────────────────────────────────────────────────────┘
```

### 2.2 关键设计原则

| 原则 | 说明 |
|---|---|
| **协议中立** | 上层业务与具体飞控/厂商解耦，PAL 层承担所有适配 |
| **无状态业务** | 业务服务水平扩展，状态下沉到 DB/Redis/Kafka |
| **实时优先** | 遥测 / 直播 / 告警走 WSS + Kafka，端到端 P95 < 500ms |
| **可离线运行** | 全部依赖可私有化部署，无外部云强依赖 |
| **插件化扩展** | AI 识别、数据后处理、UTM 对接均以插件形式接入 |
| **API-First** | 所有 Web 功能均有对应 REST / gRPC API，前端只是官方客户端 |

### 2.3 部署形态

| 形态 | 适用场景 | 硬件规模 |
|---|---|---|
| **单机 All-in-One** | POC / 演示 / 小队使用 | 1 台 16C32G |
| **小集群** | 中小机队（<50 机） | 3-5 台 K8s |
| **大集群** | 省级/国网级（>500 机） | K8s + 独立存储集群 |
| **边缘 + 中心** | 应急车 + 指挥中心 | 边缘节点 + 中心集群 |

## 3. 功能模块规格

### 3.1 设备管理（Device）
- 设备注册（序列号 / MAVLink SYSID / DJI DeviceSN）
- 设备分组与标签（按机型、部门、区域）
- 在线状态心跳（<3s 判定离线）
- 固件版本 / 参数快照
- 生命周期：入库 → 激活 → 使用 → 维护 → 报废
- **兼容清单（v1）**：PX4 v1.14+、ArduPilot 4.4+、DJI Mavic 3E/T、DJI M300 RTK、DJI Dock/Dock 2、经纬 M30、极飞 P100

### 3.2 任务规划（Mission Planning）
- 航点编辑（点击 / 导入 KML / KMZ / WPML）
- 任务模板：巡线、区域测绘、倾斜摄影、油罐环绕、垂直立面
- 航线检查：禁飞区、高度限制、电量估算、通信距离
- 任务下发：MAVLink `MISSION_ITEM_INT` / DJI WPML
- 任务复用与版本管理

### 3.3 实时监控与直播（Live Ops）
- 遥测显示：位置 / 姿态 / 电量 / 信号 / 载荷状态
- 视频直播：RTMP / WebRTC / GB28181（公安接入）
- 多路分屏：单屏 ≥ 9 路
- 电子地图：天地图 / 高德 / 离线瓦片
- 3D 态势：CesiumJS，地形 + 建筑模型
- **P95 遥测延迟** < 500ms，视频延迟 < 800ms

### 3.4 集群/编队（Swarm）
- 主从编队、分布式编队
- 冲突检测（时空四维分离）
- 任务分片与自动分配
- 应急返航 / 全体着陆
- v1 目标：单指挥员管控 ≤ 30 机

### 3.5 机场管理（Dock/Nest）
- DJI Dock / Dock 2 全生命周期
- 远程一键起飞 / 一键返仓
- 电池轮换、充放电策略
- 舱内环境（温湿度、雨感）
- 第三方机场适配层（预留）

### 3.6 数据管理（Data）
- 媒体文件回传（照片 / 视频 / 点云）
- 分类归档（任务 / 设备 / 日期 / 地理）
- 数据审计（谁看过、下载、导出）
- 与 OpenDroneMap 集成：一键建图
- 与外部 GIS 平台对接（ArcGIS / QGIS / SuperMap）

### 3.7 AI 识别（Insight）
- 插件式模型接入（ONNX / TorchScript）
- 内置模型：输电线路缺陷、光伏板热斑、违建、火点、人员车辆
- 边缘推理 + 云端复核双通道
- 结果回写为地理标注要素

### 3.8 UTM / 空域管理
- 电子围栏（禁飞区 / 限高区 / 临时空域）
- 飞行计划报备（对接民航局 UOM 接口预留）
- 冲突解脱（策略：让路 / 悬停 / 高度分离）
- Remote ID 发布与接收

### 3.9 告警与应急
- 分级告警（Info / Warn / Critical）
- 触发源：低电量、失联、越界、姿态异常、载荷异常
- 通知通道：站内、短信、企业微信、飞书、电话呼叫
- 应急预案：一键返航、就近迫降、全体悬停

### 3.10 用户与权限（RBAC）
- 多租户（组织 → 部门 → 用户）
- 角色：超级管理员 / 运营 / 飞手 / 观察员 / 审计员
- 细粒度权限（资源 × 操作）
- 三员分立（系统员 / 安全员 / 审计员，满足等保 2.0）
- SSO：OIDC / LDAP / CAS

### 3.11 审计与合规
- 全操作日志（不可篡改，追加式）
- 飞行日志留存 ≥ 3 年
- 视频加密存储（SM4 / AES-256）
- 密评合规：可选国密 SM2/SM3/SM4 通道

### 3.12 开放平台
- REST + gRPC + WebSocket 三套开放接口
- OpenAPI 3.1 规范
- 官方 SDK：Python / JavaScript / Java
- Webhook 事件总线
- 插件市场（v2）

### 3.13 生态集成模块（新增）
| 集成对象 | 用途 | 对接方式 |
|---|---|---|
| **PX4 / ArduPilot** | 飞控核心 | MAVLink over MAVROS |

| **DJI Cloud API v2** | DJI 机场/机型 | MQTT + HTTPS |

| **DroneKit-Python** | 脚本化任务编排 | 内嵌 SDK |
| **MAVProxy** | 命令行运维/调试 | 侧车模式 |

### 3.14 飞行报备审批（Flight Approval，⭐ 平台核心壁垒）

> **战略定位**：将"报备审批"从合规成本升级为**平台核心竞争力**——所有第三方平台（大疆司空、极飞、道通等）均可通过 SkyMaster 自动完成一次多头报备。

#### 3.14.1 报备主管部门矩阵

| 主管部门 | 管辖内容 | 对接方式 | 优先级 |
|---|---|---|---|
| **民航局 UOM**（中国民用航空局无人驾驶航空器一体化综合监管服务平台） | 飞行活动申请、实名登记、Remote ID、适飞空域查询、动态申请 | HTTPS + JWT（申请 API 授权） | P0 |
| **地方公安（属地公安局）** | 城市重点区域安保飞行报备 | 各地不一，多为传真/邮件/OA，可 RPA | P0 |
| **空管（军民航空管委）** | 管制空域、临时空域申请 | 电话/传真+电子表单 | P1 |
| **市场监督管理局** | 15kg 以上大型无人机登记 | 民航局系统联动 | P1 |
| **国家林草局** | 自然保护区飞行 | 邮件/OA | P2 |
| **地方文旅/城管** | 景区、城市公园 | 属地 OA | P2 |
| **海事局** | 海上/港口飞行 | 属地系统 | P2 |

#### 3.14.2 功能设计

- **一站式报备**：填一次表 → 平台按空域/属地/机型自动拆分至各主管部门
- **审批状态回执**：状态机（草稿 → 提交 → 受理 → 审批中 → 通过/驳回 → 已飞 → 已归档）
- **智能预检**：起飞前自动核对（空域、机型登记、飞手执照、保险、Remote ID 广播开关）
- **驳回原因归纳**：LLM 总结驳回原因，给出修改建议
- **三方平台反向接入**：DJI 司空 2 / 极飞 / 道通等平台调用 SkyMaster Approval API 完成报备（差异化收费）
- **合规模板库**：巡线、测绘、警务、应急预案 → 一键填充
- **报备日历**：可视化未来 30 天空域占用与自身报备排期

#### 3.14.3 数据模型
```
FlightApproval {
  id, tenant_id, mission_id,
  category (routine|special|emergency),
  airspace_polygon, altitude_range, time_window,
  authorities []{ name, external_id, status, response_ts },
  status, timeline[], attachments[]
}
```

#### 3.14.5 UOM 云系统接入门槛（🔒 核心壁垒）

> **重要认知**：UOM 后端 API **非全公开**，仅对通过《民用无人驾驶航空器云系统运营人合格证》审查的运营商开放。

**接入依据**：AC-91-FS-2016-31R1《民用无人驾驶航空器系统运营人合格证管理》 §7

**接入流程**：
```
① 递交云系统运营人合格证申请
   ↓ 材料：企业资质、系统架构、等保三级、灾备方案
② 民航局空管办受理 + 现场审查
   ↓ 周期：60–180 工作日
③ 局方分配 AK/SK + 密钥证书
   ↓
④ 沙箱环境技术对接（数据字段、心跳、Remote ID、围栏一致性）
   ↓
⑤ 试运行 3–6 个月
   ↓
⑥ 颁发正式牌照 → 正式接入
```

**授权门槛清单**：
- ✅ 企业主体（非个人/工作室）
- ✅ 信息安全等级保护三级测评证书
- ✅ 数据中心 / 灾备方案
- ✅ 无人机运行安全管理手册
- ✅ 关键岗位人员（技术负责人、运行负责人、安全负责人）
- ✅ 无人机保险（第三方责任险）

**已授权运营人参照**（截至 2025-Q4 公开新闻）：
- 大疆 DJI FlightHub 2
- 极飞 XAG Cloud
- 复亚智能
- 中航金城
- 国网通航 / 南网通航
- 顺丰无人机 / 京东无人机
- 一飞智控（EHang 编队专用）

**估算成本**：代理费 + 等保测评 + 材料准备约 **30–100 万元**

#### 3.14.6 UOM **不**承载的报备内容（属地空白 = SkyMaster 商业机会）

| 类别 | 主管方 | UOM 覆盖 |
|---|---|---|
| 属地公安备案（重点区域安保飞行） | 属地公安局 | ❌ |
| 军方管制空域申请 | 战区空管委 | ❌ |
| 自然保护区/国家公园飞行 | 林草局属地机构 | ❌ |
| 海关/海事管辖区 | 海事局属地 | ❌ |
| 大型活动/展会临时管制 | 属地公安 + 主办方 | ❌ |

> **价值命题**：UOM 只解决"通用航空侧合规"，属地公安 / 文旅 / 林草侧仍是**报备平台空白**，是 SkyMaster 最大的差异化机会。

### 3.15 三维实景与 4DGS 增值模块（Reality Studio）

> **定位**：付费增值模块，将航测数据一键转化为高保真三维/时序四维场景。

#### 3.15.1 功能矩阵

| 能力 | 技术方案 | 输出 |
|---|---|---|
| **正射影像 / DSM** | OpenDroneMap / MetaShape SDK | GeoTIFF |
| **点云** | OpenMVS / COLMAP | LAS/PLY |
| **倾斜摄影 OSGB** | ContextCapture 网关（可选） | OSGB Tile |
| **3D Gaussian Splatting** | 集成 nerfstudio / gsplat 训练管线 | `.splat` / `.ply` |
| **4D Gaussian Splatting** | 时序 4DGS（同一区域周期采集，形变分析） | 时间序列 splat |
| **在线渲染** | Cesium + gsplat-cesium-plugin | Web 直接查看 |
| **变化检测** | 4DGS 差分 → 高亮变化区域 | 报告 + 标注 |

#### 3.15.2 典型场景
- 电力铁塔时序形变监测（4DGS 逐月对比）
- 建筑工地进度可视化（4DGS 沿时间轴回放）
- 应急救援实时三维态势（3DGS 快速建模）
- 数字孪生城市局部更新（增量重建）

#### 3.15.3 商业模式
- 免费额度：每租户 10 GB 素材/月
- 增值：GPU 训练时按分钟计费；托管渲染按流量计费
- 私有部署：一次性 License + 年度维护

#### 3.15.4 技术要求
- GPU 集群（A100/H100 或国产 910B）
- 训练流水线：入库 → 预处理 → 稀疏重建 → 稠密重建 → GS 训练 → 发布
- 单场景 3DGS 训练时长 P95 < 30 分钟（1000 张图 @ A100×1）
- 支持渐进式加载与 LOD

### 3.16 AI 感知模块（Vision AI）

> **定位**：从 3.7 节 Insight 升级为**独立业务域**，覆盖检测/识别/跟踪/分割/异常检测全谱系。

#### 3.16.1 能力清单

| 类别 | 任务 | 内置模型基线 |
|---|---|---|
| **检测** | 车辆、人员、船舶、施工机械 | YOLOv10 / RT-DETR |
| **识别** | 车牌、人脸（合规下）、船名、缺陷种类 | PaddleOCR / ArcFace |
| **跟踪** | 单目标 SOT、多目标 MOT | ByteTrack / BoT-SORT |
| **分割** | 违建、水体、火点、光伏板 | SAM 2 / YOLOv8-seg |
| **异常检测** | 输电线路螺栓/绝缘子、光伏热斑 | PatchCore / EfficientAD |
| **姿态/行为** | 落水者、聚集事件 | RTMPose / SlowFast |
| **变化检测** | 违建新增、林地砍伐 | ChangeFormer |

#### 3.16.2 系统架构
```
视频/图像流 → Edge Inference Runtime (Triton/ONNX Runtime)
             ↓ 事件/框
         Kafka events.detection
             ↓
        规则引擎 → 告警/工单/地理标注
             ↓
        云端复核（大模型 VLM 二次判定）
```

#### 3.16.3 关键特性
- **插件化模型接入**：ONNX/TorchScript/TensorRT/RKNN/Ascend OM 全支持
- **边缘 + 云端双通道**：低延迟边缘检测 + VLM 云端复核降误报
- **在线学习**：用户标注纠错 → 增量微调 → 一键上线
- **国产化推理**：昇腾 310B / 寒武纪 MLU / 瑞芯微 RK3588 适配
- **VLM 集成**：Qwen2.5-VL / InternVL 用于开集识别与自然语言查询（"找出画面里所有戴红色安全帽的人"）

## 附录 B · 术语表

- **GCS**：Ground Control Station 地面控制站
- **UTM**：Unmanned Traffic Management 无人机交通管理
- **UOM**：民航局无人驾驶航空器一体化综合监管服务平台
- **PAL**：Protocol Abstraction Layer 协议抽象层
- **SITL**：Software In The Loop 软件在环仿真
- **Remote ID**：远程识别广播（类似汽车牌照）
- **WPML**：DJI Waypoint Markup Language
- **OSDK**：DJI Onboard SDK
- **3DGS**：3D Gaussian Splatting 三维高斯泼溅重建
- **4DGS**：时空高斯泼溅（含时间维度）
- **AOC**：无人机运行合格证（Air Operator Certificate）
- **RPA**：Robotic Process Automation 机器人流程自动化
- **AaaS**：Approval-as-a-Service 报备即服务
- **U-Cloud**：UOM 云系统数据上报通道
- **AK/SK**：Access Key / Secret Key 云系统接入密钥
- **WHIP/WHEP**：WebRTC 低延迟推流/拉流协议

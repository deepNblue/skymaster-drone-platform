## 四、100 机能力四场景压测结果

| 场景 | 覆盖范围 | P95 延迟 | SLA 富余 |
|---|---|---|---|
| **A** · 应用层内联 | WebSocketManager 纯代码 | 0.54 ms | **926×** |
| **B** · 真 WS 网络栈 | uvicorn+FastAPI+TCP | 4.98 ms | **100×** |
| **C** · REST API | 50 并发 × 4 端点 | 17-36 ms | **5.6-11.6×** |
| **D** · 数据库入库 | SQLite batch+WAL | 7.40 ms | **13×** |

**意外收获**：一次实验证明"批量入库 ≠ 更快"的直觉陷阱——`batch` 不开 WAL 反而比 `single` 慢 80×，`batch+WAL` 才是真最优。

## 六、开发方法论沉淀

### ✅ 已验证有效的方法

1. **Subagent + tmux 并行开发**：v2.0 阶段大量任务用 clawteam 模式并行推进，效率倍增
2. **CI 门禁**：`backend-load-test.yml` 让 SLA 判定自动化，PR 无法带着性能问题合并
3. **UAT 端到端测试**：一个测试覆盖 9 步完整业务链路，比 60 个单元测试价值高
4. **性能对比实验**：场景 D 的三策略对比揭示了非直觉的性能陷阱

### ⚠️ 待改进项

1. **v0.1 与 v0.2 双目录**：`backend`/`backend-v0.1` 并存，需在 v2.1 前收敛
2. **UOM 生产账号**：T7.2 深圳 ATC e-Form Playwright 集成仍卡在生产账号凭证
3. **仅场景 A 进 CI**：B/C/D 需 uvicorn 或独立进程编排，暂未进 CI

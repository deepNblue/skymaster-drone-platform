## 二、v2.x 分版本节奏（建议）

### 🎯 v2.0（3 个月）— 合规护城河 + AI 底座
**核心叙事**：政企客户购买 SkyMaster 的第一理由不再是"能管所有机型"，而是"能一站式合法起飞"。

- ✅ 飞行报备审批模块（§3.14）
  - UOM API 授权申请与打通
  - 报备数据模型 + 状态机
  - 属地公安 RPA 提交（先 3 个试点城市）
  - Approval-as-a-Service 对外 API（v2 试点）
- ✅ Vision AI 底座（§3.16 前半）
  - 边缘推理运行时（Triton / ONNX Runtime）
  - YOLOv10 + SAM 2 内置基线
  - 事件总线 + 规则引擎

### 🎯 v2.1（3 个月）— 三维可视化 + Agent 化操作
- ✅ Reality Studio（§3.15）
  - 3DGS 训练流水线（nerfstudio + gsplat）
  - Web 端 Cesium + gsplat 在线查看
  - 4DGS 时序差分 MVP
- ✅ Copilot & Auto-Ops（§3.17）
  - L1 Chat Copilot（Function Calling 全平台 API）
  - L2 Workflow Agent（3 个官方 Playbook：早查、应急、合规巡查）

### 🎯 v2.2（3 个月）— 生态 + 长尾能力
- ✅ Vision AI 全谱系（§3.16 后半）
  - 跟踪 / 分割 / 异常检测 / 变化检测 / 姿态行为
  - 国产化推理适配（昇腾 310B / RK3588）
  - VLM 集成（Qwen2.5-VL / InternVL）
- ✅ Community（§3.18）
  - 论坛、飞手圈、模型广场、开发者专区
  - 与 GitHub Issues 双向打通
- ✅ Model Marketplace v1（§3.19）
  - 模型上架 + 免费/买断/订阅三种模式
  - 分账系统（作者 70% / 平台 30%）

### 🎯 v2.3（3 个月）— 训练即服务 + 反向开放
- ✅ Training-as-a-Service（§3.19 后半）
  - 一键微调（数据 → 训练 → 发布闭环）
  - GPU 池（本地 + 混合云）
- ✅ Approval-as-a-Service 生产级
  - 30 个重点城市覆盖
  - DJI 司空 2 / 极飞 / 道通反向接入 SkyMaster

## 三、v2.0（近期 3 个月）细化任务分解

### Track A · 飞行报备审批（P0，核心壁垒）

#### A1 前置调研（2 周）
- [ ] 民航局 UOM 平台 API 授权申请路径（走什么部门？多久？是否需要 ICP + 等保？）
- [ ] UOM 现有对外接口清单（实名登记、适飞空域、动态申请、Remote ID 上报）
- [ ] 属地公安（先选 3 个城市：北京、成都、深圳）报备现状调研
- [ ] 现有已对接的第三方平台（司空 2 / 极飞 / 道通）报备流程调研
- [ ] 竞品分析：智翔通用航空、AOPA 智飞、飞常准 UOM

**产出**：《飞行报备审批调研报告.md》

#### A2 数据模型 + 状态机（1 周）
```
数据表
- flight_approvals              主表
- approval_authorities          每个报备涉及的主管部门（多对多）
- approval_timeline             状态流转历史
- approval_attachments          附件（申请表、审批回执等）
- approval_templates            合规模板（巡线/测绘/警务）
- airspace_calendar             空域占用日历
```
状态机：`draft → submitted → accepted → reviewing → approved|rejected → flying → completed → archived`

#### A3 UOM 对接实现（3 周）
- [ ] UOM OAuth / 密钥对接（申请授权期间可先做 Mock）
- [ ] 实名登记同步（用户/无人机机身信息）
- [ ] 适飞空域查询（缓存 + 离线包）
- [ ] 飞行活动申请提交 + 回执订阅
- [ ] Remote ID 上报通道

#### A4 属地公安 RPA + OA 通道（2 周）
- [ ] 邮件模板自动生成（合规格式）
- [ ] 电子表单填充 + 提交（Playwright / 电子章）
- [ ] 状态回执采集（邮件回复解析 + 人工上传补录）

#### A5 三方平台反向接入（2 周）
- [ ] SkyMaster Approval Open API v1
- [ ] 认证接入方案（合作方发放 AK/SK）
- [ ] 试点：让本平台自身的司空 2 桥接以"外部租户"身份走 SkyMaster 报备（自食其狗粮）

#### A6 前端交互（2 周，与后端并行）
- [ ] 报备向导（5 步：任务 → 空域 → 机组 → 附件 → 提交）
- [ ] 报备日历
- [ ] 智能预检（起飞前红黄绿灯）
- [ ] 驳回原因 LLM 归纳

---

### Track B · Vision AI 底座（P0）

#### B1 边缘推理运行时（2 周）
- [ ] 选型：Triton Inference Server + ONNX Runtime
- [ ] Docker 镜像（含 CUDA / CPU / RKNN 三分支）
- [ ] 模型加载 hot-reload
- [ ] 性能基准（YOLOv10n @ 1080p，Jetson Orin Nano 目标 ≥ 15 FPS）

#### B2 事件总线（1 周）
- [ ] Kafka topic 设计（events.detection / events.tracking / events.anomaly）
- [ ] Event schema（proto/avro）

#### B3 规则引擎（2 周）
- [ ] 简单 DSL（IF 检测=人员 AND 区域=禁入区 THEN 告警级=critical）
- [ ] 规则回测（历史视频重跑）

#### B4 内置模型（3 周）
- [ ] YOLOv10n / s / m 训练完成的通用检测模型
- [ ] SAM 2 web 端交互式分割
- [ ] 输电线路缺陷模型（迁移自 §3.7 原有 Insight）

---

### Track C · 基础设施升级（伴随 A + B）

- [ ] 消息队列 Kafka 集群化（当前若为单节点需升级）
- [ ] 对象存储 MinIO 分级存储（热/温/冷）
- [ ] GPU 节点纳入 K8s（NVIDIA device plugin）
- [ ] Vault / Sealed-Secrets（UOM 密钥需要更严的密管）

## 四、v2.1 关键路径预告（提前埋点）

## 五、风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| **UOM API 授权申请周期长** | Track A 交付延迟 | 前 2 周并行做 Mock 数据模型；先跑通业务闭环；授权到位后接入正式接口 |
| **属地公安报备流程各地差异极大** | RPA 难以标准化 | 先选北上广深成 5 城做深度适配，其他城市走"模板+人工确认"降级方案 |
| **GPU 集群成本高** | Reality Studio / 训练服务毛利被侵蚀 | 与 GPU 云厂商谈战略价 + 弹性扩缩容 |
| **Model Marketplace 早期缺内容** | 冷启动困难 | 官方先上架 20+ 常用模型；引入 3 家算法合作伙伴 |
| **社区内容合规** | 涉军涉密风险 | LLM 前置审核 + 关键词库 + 举报队列 + 人工兜底 |
| **Agent 误操作起飞** | 安全事故 | L2/L3 强制人工二次确认；沙箱模拟先跑；启动权限单独审批 |
